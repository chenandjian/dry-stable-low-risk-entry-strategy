# TickFlow 免费与认证模式人工切换设计

## 1. 目标

为 TickFlow 增加明确的人工访问模式配置。系统默认使用免费模式；只有用户明确选择认证模式时才使用已保存的 API Key。模式之间不得自动判断、自动切换或失败降级。

## 2. 配置契约

在 `data` 下新增：

```yaml
tickflow_access_mode: free
tickflow_api_key: ""
```

- `tickflow_access_mode` 只允许 `free`、`authenticated`。
- 旧配置缺少该字段时按 `free` 处理。
- `free` 是默认值。
- 切换模式不删除、覆盖或清空已保存的 `tickflow_api_key`。
- API Key 不校验 `tk_` 等供应商前缀。

## 3. 运行语义

### 3.1 免费模式

- 无条件调用 `TickFlow.free()`。
- 即使配置文件、环境变量或默认常量中存在 Key，也不得调用认证构造函数。
- Key 仅保留，不参与当前任务。

### 3.2 认证模式

- 无条件调用 `TickFlow(api_key=resolved_key)`。
- Key 解析顺序保持：配置 Key、`TICKFLOW_API_KEY` 环境变量、项目默认 Key。
- 无可用 Key 时明确失败，不得降级到免费模式。

### 3.3 一致调用链

以下入口必须在任务开始时读取并固定同一个访问模式：

1. 策略扫描前 TickFlow 批量行情准备。
2. 前端触发的 TickFlow 全市场重拉。
3. TickFlow 股票和四个指数的数据新鲜度测试。
4. 定时扫描间接调用的行情准备流程。

全量后台任务应只在内存参数中持有模式和 Key，不得把 Key写入任务状态、进度 JSON 或报告。模式可以作为非敏感审计信息展示。

## 4. 配置接口

### GET `/api/config`

- 返回 `tickflow_access_mode`，旧配置补齐为 `free`。
- `tickflow_api_key` 始终返回空字符串。
- 返回 `tickflow_api_key_configured` 表示认证模式是否有可解析 Key，不代表当前正在使用认证模式。
- 不修改 `load_config()` 返回的原始对象。

### PUT `/api/config`

- 模式缺失：保留原模式；旧配置无原模式时仍由运行时默认 `free`。
- 模式为 `free` 或 `authenticated`：保存人工选择。
- 其他模式或非字符串：返回 HTTP 400，不写配置。
- Key 缺失或空白：保留旧 Key。
- Key 非空字符串：去除首尾空格后替换。
- 保存模式或 Key 后立即重载 scheduler，保证后续定时任务使用新配置。

## 5. 前端设计

策略配置页的 TickFlow 区域增加两个单选项：

- `免费模式（默认）`
- `API Key 认证模式`

行为：

- 免费模式下隐藏 Key 编辑框，显示“已保存的 Key 会保留，但当前不会使用”。
- 认证模式下显示密码输入、显示/隐藏按钮和“已配置/未配置”状态。
- 页面加载旧配置时选择免费模式。
- 保存免费模式时不提交空白 Key，因此不会清除已保存 Key。
- 保存认证模式时，空白 Key 仍表示保留；新输入值才替换。
- 前端不得根据 `tickflow_api_key_configured` 自动改变模式。

## 6. 错误处理

- 免费模式 SDK 初始化失败：原样按 TickFlow 免费服务错误报告。
- 认证模式 Key 缺失或 SDK 认证失败：明确报告认证模式错误。
- 两种模式均不得自动切换到另一种模式。
- 异常信息、日志、API 返回、任务状态中不得包含 Key 明文。

## 7. 测试要求

### 后端

- 客户端默认模式调用 `TickFlow.free()`。
- 免费模式存在 Key 时仍只调用 `TickFlow.free()`。
- 认证模式只调用 `TickFlow(api_key=...)`，绝不调用免费模式。
- 非法模式被拒绝。
- 扫描、全量重拉、新鲜度检查传递正确模式。
- 任务状态和报告不含 Key。
- GET 脱敏并补齐默认免费模式。
- PUT 模式保存、非法模式拒绝、切换免费后 Key 保留、scheduler 重载。

### 前端

- 旧配置默认显示免费模式。
- 免费模式隐藏 Key 输入并显示保留提示。
- 认证模式显示 Key 输入。
- 模式选择严格进入请求体，不受 Key 配置状态影响。
- 免费模式保存不提交空白 Key。
- 认证模式新 Key 去空格后提交并在成功后清空输入。

## 8. 非目标

- 不改变 TickFlow 批量参数、前复权方式、增量/全量写入逻辑。
- 不改变传统多数据源模式。
- 不增加认证失败自动回退。
- 不修改策略1至策略6选股逻辑。

## 9. 验收标准

1. 默认和旧配置均使用 `TickFlow.free()`。
2. 有 Key 但选择免费模式时仍使用 `TickFlow.free()`。
3. 只有人工选择认证模式才使用 Key。
4. 模式切换保留 Key，且不泄漏明文。
5. 所有 TickFlow 入口行为一致。
6. 后端、前端专项和完整回归通过。

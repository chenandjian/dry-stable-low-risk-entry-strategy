# 策略6完整VCP轮次识别优化设计

## 1. 目标

在不改变策略6扫描入口、主候选旧字段和策略1至策略5行为的前提下，修复策略6主链与独立VCP观察池共同使用的错误峰谷识别逻辑。

新规则直接处理全市场原始日线。一轮完整VCP收缩必须包含“起始峰值 -> 最终低点 -> 有效反弹峰值”，不能再把单独的峰值到低点下跌段计为一轮。主链和观察池共享同一个完整轮次检测核心，避免两套口径再次漂移。

## 2. 已确认的问题

当前 `strategy6/pattern.py::_swing_contractions()` 将任意局部峰值到下一局部峰值前最低收盘视为一段收缩，`_best_vcp_chain()` 只比较下跌幅度、平均成交量和低点位置，不要求低点后出现有效反弹。

因此会出现：

- 持续深跌被识别为第一轮收缩；
- 低点次日不足 3% 的微弱反抽被识别为下一轮峰值；
- 主链错误获得 VCP 形态分；
- 错误的末轮低点和峰值进入支撑聚类、枢轴点、止损、目标和盈亏比计算；
- 独立观察池只能在旧算法预筛出的股票中继续做历史资格检查，形成旧候选样本偏差。

## 3. 完整轮次定义

### 3.1 一轮的必要组成

每轮必须包含：

1. 起始峰值 `peak`；
2. 峰值后的最终最低收盘 `low`；
3. 低点后的有效反弹峰值 `recovery_peak`。

收缩幅度：

```text
amplitude = (peak_close - low_close) / peak_close
```

反弹幅度：

```text
rebound = (recovery_peak_close - low_close) / low_close
```

下一轮起始峰值与上一轮反弹峰值是同一个价格节点。

### 3.2 弱反抽合并

- 低点后的累计反弹不足 `3%` 时，不建立反弹峰值；
- 弱反抽后再次创新低时，原低点作废，继续延长当前下跌段；
- 普通反弹至少经过低点后的两个可见交易日，且在确认前不得再次创新低；
- 反弹峰值需要后续回落确认，避免把仍在上涨的最新价格提前冻结为峰值；
- 若收盘直接突破本轮起始峰值，并满足单日涨幅不低于 `5%` 或相对前 20 日均量的量比不低于 `1.2`，可在突破日直接确认本轮完成。

### 3.3 第一轮约束

- 第一轮收缩幅度最低 `8%`；
- 第一轮收缩幅度最高 `32%`；
- 不使用“连续下跌天数”作为硬条件；
- 第一轮峰值之前必须存在有效的策略6强势启动；
- 带有 `failure_reasons` 的历史启动事件不得作为VCP起点。

### 3.4 后续轮次约束

- 后一轮收缩幅度必须小于前一轮的 `90%`；
- 后一轮下跌阶段平均成交量必须小于前一轮的 `90%`；
- 后一轮低点不得低于前一轮低点的 `97%`；
- 低点较上一轮下降超过 `1%` 但未超过 `3%` 时保留结构并输出风险提示；
- 低点持平或抬高时增加质量分；
- 小于 `1%` 的末轮收缩作为微小波动风险提示，不单独作为硬淘汰条件。

下跌阶段均量不包含起始峰值，只统计峰值后的下跌过程；反弹阶段均量不包含低点，只统计低点后的回升过程。

## 4. 状态模型

共享检测核心输出以下结构状态：

- `VCP_NONE`：没有有效完整轮次；
- `VCP_ROUND1_FORMING`：第一轮下跌或反弹尚未确认；
- `VCP_ROUND1_CONFIRMED`：第一轮完整，下一轮尚未完成；
- `VCP_CONFIRMED`：至少两轮完整且逐轮收紧；
- `VCP_NEAR_PIVOT`：确认结构仍有效且接近最后反弹峰值；
- `VCP_BREAKOUT_CONFIRMED`：最后一轮发生有效突破；
- `VCP_POST_BREAKOUT`：有效突破后的保留期；
- `VCP_EXTENDED`：突破后偏离枢轴过远；
- `VCP_INVALID`：结构低点、关键支撑或放量风险使结构失效。

正式VCP形态要求至少两轮完整收缩。第一轮完整、第二轮形成中的股票只能进入“VCP早期观察”，不得获得主链正式VCP形态分。

## 5. 共享检测核心

新增策略6专用模块 `strategy6/vcp_rounds.py`，职责仅为：

- 从归一化、按交易日升序的日线中识别完整轮次；
- 合并无效反抽；
- 输出形成中轮次、完整轮次、枢轴点、结构低点；
- 输出每轮价格和成交量证据；
- 不读取数据库，不决定正式候选，不计算交易计划。

`strategy6/pattern.py` 与 `strategy6/vcp_observer.py` 都调用该模块：

- 主链在整理阶段窗口上调用，至少两轮完整时返回 `pattern_type=VCP`；
- 观察池在配置的最近 60 个交易日窗口上调用，允许保存第一轮完整、第二轮形成中的早期观察状态；
- 两个调用方不得再次自行实现峰谷拼接规则。

## 6. 主链接入

主链保留 `detect_pattern()` 入口和杯柄、VCP、平台的现有识别顺序。VCP分支改为读取完整轮次结果：

- `pattern_score` 只根据完整轮次数和质量生成；
- `contraction_count` 改为完整轮次数；
- `pattern_start_date` 为第一轮起始峰值日期；
- `pattern_end_date` 为最后完整轮反弹峰值日期；
- `pivot_price` 为最后完整轮反弹峰值；
- `pattern_low` 为最后完整轮低点；
- 不完整轮次不得生成 `PATTERN_LOW` 或主链VCP形态分。

旧输出字段不得删除。轮次证据新增反弹峰值日期、价格、反弹幅度、下跌均量和反弹均量。

## 7. 观察池接入

观察池直接使用新核心，不再依赖旧 `_swing_contractions()` 和 `_best_vcp_chain()`。

- 第一轮完整且第二轮形成中：标记为早期观察；
- 至少两轮完整：标记为确认候选；
- 当前结构必须继续满足历史正式候选资格；
- 历史资格回放只依赖新VCP结构起点，不得由旧VCP结果限制候选宇宙；
- `SUPPORT_FAILED`、`BIG_DOWN_VOLUME`、`DISTRIBUTION_PRESSURE_HIGH`、不可恢复的支撑放量破位会使早期观察失效；
- 纯观察记录继续使用 `REJECTED/observation`，不得混入策略6主候选。

## 8. 质量评分

`strategy6/vcp_quality.py` 改为使用完整轮次证据，保持总分 100 和只排序、不影响正式策略资格的边界：

- 完整轮次数：15；
- 收缩幅度逐轮收窄：20；
- 下跌成交量逐轮收缩：20；
- 低点持平或抬高：15；
- 启动涨幅保留：10；
- 枢轴逐渐收紧：10；
- 时间结构：5；
- 突破质量：5。

旧任务已有质量分保持原快照，不执行历史数据迁移或重算。

## 9. 配置

新增并显式写入策略6配置：

```yaml
vcp_first_contraction_max_range: 0.32
vcp_rebound_min_pct: 0.03
vcp_rebound_confirm_days: 2
vcp_low_warning_ratio: 0.99
```

继续复用：

```yaml
vcp_min_first_range: 0.08
vcp_contraction_range_ratio: 0.90
vcp_contraction_volume_ratio: 0.90
```

配置解析必须有固定默认值和边界校验，旧配置缺失新增字段时行为可预测。

## 10. 前端与兼容

前端VCP区域继续与市场过滤、重点候选、观察候选同级展示，并区分：

- `VCP确认候选`；
- `VCP早期观察`。

每轮展示：

- 起始峰值日期和价格；
- 最终低点日期和价格；
- 反弹峰值日期和价格；
- 收缩幅度；
- 反弹幅度；
- 下跌均量相对上一轮的比例。

旧API字段保持不变；新增字段只能以兼容方式追加。旧任务缺少新字段时显示“旧任务未记录”，不得伪造完整轮次。

## 11. 测试与验收

单元测试必须覆盖：

1. `603505` 深跌加弱反抽不能形成完整第一轮；
2. `000703` 的 `07-10` 弱反抽被合并，第一轮重划为 `07-06 -> 07-13 -> 07-14`；
3. `002156` 两轮完整且第二轮直接突破；
4. `002056` 只有第一轮完整，进入早期观察而非确认候选；
5. 弱反抽后创新低会替换最终低点；
6. 普通反弹需要时间和回落确认；
7. 强势直接突破可立即完成轮次；
8. 第一轮超过 32% 被排除；
9. 后续幅度、下跌量和低点约束分别生效；
10. 失败的历史启动不能作为起点；
11. 主链和观察池对相同窗口输出相同轮次证据；
12. 主链假VCP不再获得形态分、形态支撑和枢轴点；
13. 策略1至策略5测试不受影响；
14. 旧任务API和前端渲染兼容。

真实验收使用本地 `data/cuphandle.db`：

- 对全市场本地日线重新执行策略6评估，不能只过滤旧VCP候选；
- 报告确认候选、早期观察、排除数量及股票清单；
- 对比修复前后的主候选、VCP形态、支撑位和总分变化；
- 单独核对 `603505`、`000703`、`002156`、`002056`；
- 回测和历史逐日重放严格按 `evaluation_date` 截断，不得使用未来日线。

## 12. 非目标

- 不修改策略1至策略5；
- 不调整策略6主候选分数阈值和盈亏比阈值；
- 不把VCP质量分加入策略6总分；
- 不使用网络数据；
- 不覆盖现有用户修改或重算旧任务快照。

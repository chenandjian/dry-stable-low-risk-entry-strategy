# 策略6市场降级前候选等级展示设计

## 目标

策略6在 `market_filter_mode=downgrade` 且市场偏弱时，会把原本满足重点候选或就绪候选条件的股票归入观察候选。前端需要明确展示真实的降级前等级，让用户能区分“原本强势、因市场环境降级”和“本来只满足观察条件”。

## 设计

- 策略判断新增兼容字段 `pre_market_candidate_type`，仅记录市场弱势过滤前的候选等级。
- 只有最终等级为 `WATCH_CANDIDATE`，且过滤前等级为 `READY_CANDIDATE` 或 `KEY_CANDIDATE` 时保存该字段。
- 本来就是观察候选的股票保持空值，不显示“原重点/原就绪”。
- 评分、最终候选等级、市场过滤方式和策略1至策略5均不改变。
- SQLite 使用兼容迁移新增可空文本列，旧任务读取为空。
- 前端候选列表和详情显示“原重点候选 · 因市场偏弱降级”或“原就绪候选 · 因市场偏弱降级”。CSV 增加降级前候选等级列。
- 旧任务只有 `MARKET_WEAK_DOWNGRADED` 警告但没有新字段时，显示“市场降级 · 原等级未记录”，禁止根据分数猜测等级。

## 验证标准

1. 弱市场将重点/就绪候选降为观察时，后端输出准确的原等级。
2. 弱市场下本来就是观察候选时，原等级为空。
3. 关闭市场过滤或使用 `score_only` 时，原等级为空。
4. 新字段可以写入并从 SQLite 读取，旧数据库自动迁移。
5. 前端列表、详情和 CSV 均能解释降级，旧任务显示兼容提示。

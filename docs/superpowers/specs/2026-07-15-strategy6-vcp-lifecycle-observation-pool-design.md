# 策略6 VCP生命周期观察池设计

## 1. 目标

在策略6现有 `StrongVcpTailEngine.evaluate_at()`、扫描入口、候选表和前端结果页基础上，新增“VCP形态记忆与生命周期观察池”。

本功能解决两类漏识别：

1. VCP最后一次收缩被划入尾段后，主形态检测窗口看不到完整收缩链。
2. VCP突破日被识别为新的强势启动后，原VCP身份被新启动重置，前端显示 `UNKNOWN`。

目标不是绕过策略6风险规则产生买入信号，而是保证已经形成的VCP能够进入独立观察视图，并持续显示其形成、接近支点、突破、突破后延伸和失效状态。

## 2. 已确认业务口径

- 不新增独立策略，不新增扫描入口。
- 继续使用策略6唯一入口 `StrongVcpTailEngine.evaluate_at()`。
- VCP观察身份与重点/观察交易分类是两个独立维度。
- 前端新增与“市场过滤数据”“重点候选”“观察候选”同级的“VCP形态候选”板块。
- VCP股票仍保留在原有重点候选或观察候选板块中，允许重复展示。
- VCP成立至少进入独立VCP观察板块，但不能因此自动升级为重点或就绪候选。
- 距离支点过远、量能未干或盈亏比不足时，只显示观察和风险提示，不提供追高买入建议。
- 放量破位、跌破VCP结构低点、数据不足和流动性不合格等硬风险仍可使VCP失效或排除。
- 不修改策略1至策略5。

## 3. 根因

当前调用顺序为：

1. 选择一个强势启动事件。
2. 依据该启动事件划分整理区和尾段。
3. 只在 `consolidation_start_index:tail_start_index` 中识别杯柄、VCP和平台。
4. 新的高质量启动事件可以替换旧启动事件。

以 `002156` 为例：

- 2026-06-30至2026-07-03收缩幅度约14.59%。
- 2026-07-07至2026-07-08收缩幅度约3.81%。
- 后一次平均成交量低于前一次，低点由64.80抬高至65.61。
- 2026-07-09发生涨停突破。

在7月8日，第二次收缩被放入尾段，整理区看不到完整链；在7月9日，涨停被选为新S/A级启动，阶段变为 `START_TOO_RECENT`，形态检测直接返回 `UNKNOWN`。因此该VCP没有连续的形态身份。

## 4. 方案选择

### 方案A：VCP生命周期观察器，采用

在策略6引擎内部增加独立于主阶段切分的VCP生命周期分析。观察器只提供形态证据和观察资格，所有重点/就绪分类仍走原主链。

优点：改动边界清楚，不改变杯柄、BOX、Brooks和现有尾部逻辑；能够保存突破前VCP身份。

### 方案B：重写主阶段切分，不采用

让主形态检测直接包含尾段，并阻止新启动覆盖旧启动。该方案会同时改变杯柄、平台、BOX、Brooks和支撑计算，回归范围过大。

### 方案C：新增独立VCP扫描器，不采用

建立新的扫描入口和候选表会破坏策略6统一入口，并形成两套不可追溯的候选判断链。

## 5. VCP观察器

新增策略6专用模块 `strategy6/vcp_observer.py`。模块只读取评估日及以前的K线，输出 `Strategy6VcpObservation`，不直接写数据库或决定重点/就绪等级。

### 5.1 搜索窗口

- 默认观察最近60个交易日。
- 搜索窗口允许使用通过事件日强势条件、但后续发生回撤的历史启动作为结构起点。
- 历史启动的失败原因保留为风险标签，不能直接抹除后续重新形成的VCP。
- 当前新启动只用于判断突破，不清除已经确认的观察形态。

### 5.2 最低形态条件

VCP观察形态至少需要两个有先后顺序的收缩段：

- 第一段振幅不低于现有 `vcp_min_first_range`。
- 后一段振幅小于前一段振幅乘以现有 `vcp_contraction_range_ratio`。
- 后一段平均成交量小于前一段平均成交量乘以现有 `vcp_contraction_volume_ratio`。
- 后一段低点不低于前一段低点的97%。
- 收缩段之间不能存在已经确认且未收复的放量结构破位。

优先复用 `strategy6.pattern` 中的收缩计算口径，提取公共纯函数时不得改变现有主形态结果。

### 5.3 生命周期状态

| 状态 | 含义 | 候选处理 |
|---|---|---|
| `VCP_FORMING` | 两次以上收缩成立，但尚未接近支点 | 进入VCP观察板块 |
| `VCP_NEAR_PIVOT` | 当前价位于支点下方允许范围内 | 进入VCP观察板块 |
| `VCP_BREAKOUT_CONFIRMED` | 收盘突破支点，且突破日为有效强势启动或量价确认 | 进入VCP观察板块，原主链决定交易等级 |
| `VCP_POST_BREAKOUT` | 突破后仍保持在支点和结构低点之上 | 继续观察 |
| `VCP_EXTENDED` | 突破后明显偏离支点 | 继续观察但禁止立即买入语义 |
| `VCP_INVALID` | 跌破结构低点或放量破位且未收复 | 不进入VCP观察板块 |
| `VCP_NONE` | 未形成有效VCP | 不进入VCP观察板块 |

突破后的默认观察期为10个交易日。超过观察期且没有形成新的低风险结构时，不再出现在VCP观察板块；历史任务记录仍保留。

### 5.4 支点和失效位

- VCP支点使用最后一个有效收缩段的峰值收盘价，保持与现有VCP口径一致。
- VCP结构低点使用最后一个有效收缩段低点。
- 当前价距离支点：`current_close / vcp_pivot_price - 1`。
- 收盘跌破结构低点，或出现放量跌破后3个交易日内未收复，状态变为 `VCP_INVALID`。
- `VCP_EXTENDED` 只影响观察提示和交易语义，不删除历史VCP身份。

## 6. 候选分类

### 6.1 双维度模型

交易维度继续使用：

- `READY_CANDIDATE`
- `KEY_CANDIDATE`
- `WATCH_CANDIDATE`
- `REJECTED`

形态观察维度新增：

- `vcp_observation_eligible`
- `vcp_lifecycle_status`

两者互不替代。同一股票可以同时属于“VCP形态候选”和“重点候选”或“观察候选”。

### 6.2 VCP观察资格

满足以下条件时进入VCP观察板块：

1. `vcp_lifecycle_status` 为 `VCP_FORMING`、`VCP_NEAR_PIVOT`、`VCP_BREAKOUT_CONFIRMED`、`VCP_POST_BREAKOUT` 或 `VCP_EXTENDED`。
2. 数据量、均线计算和基础流动性有效。
3. 未发生VCP结构低点失效或未收复的放量破位。

尾部成交量未干、尾部振幅偏大、盈亏比不足、当前距离支点过远等不能生成可执行买点，但可以保留VCP观察资格，并转为观察风险标签。

扫描器不能仅依赖 `evaluation.passed` 保存VCP观察记录。策略6结果持久化需要同时保存：

- 原交易候选；或
- `vcp_observation_eligible=true` 的独立观察记录。

这不会把观察记录伪装成 `KEY_CANDIDATE` 或 `READY_CANDIDATE`。

## 7. 输出字段

只新增字段，不删除或改名旧字段：

- `vcp_observation_eligible`
- `vcp_lifecycle_status`
- `vcp_origin_start_date`
- `vcp_pattern_start_date`
- `vcp_pattern_end_date`
- `vcp_contraction_count`
- `vcp_contractions`
- `vcp_pivot_price`
- `vcp_structure_low`
- `vcp_distance_to_pivot_pct`
- `vcp_breakout_date`
- `vcp_days_since_breakout`
- `vcp_observation_reasons`
- `vcp_observation_risk_tags`
- `vcp_invalidation_reason`

旧 `pattern_type` 保持主形态语义。前端VCP观察板块使用新的观察字段，避免用观察证据暗中改变主评分和主交易分类。

## 8. 数据库与兼容性

- 在 `strategy6_candidates` 使用 `_ensure_column()` 增量增加标量和JSON字段。
- 旧任务缺失字段时返回 `false`、`VCP_NONE`、空数组或空字符串。
- 旧任务不能因为迁移默认值而被显示为VCP候选。
- API继续使用原策略6候选接口，返回新增字段。
- 生命周期退出审计需要记录VCP观察资格退出和失效原因。

## 9. 前端设计

策略6结果页板块顺序：

1. 市场过滤数据
2. VCP形态候选
3. 重点候选
4. 观察候选

VCP形态候选与重点/观察候选同级，不是二级Tab，也不从原分组移除股票。

板块表格展示：

- 股票代码与名称
- VCP状态
- 收缩次数
- VCP支点
- 结构低点
- 当前价距离支点
- 突破日期
- 总分
- 原交易分类
- 风险提示

点击股票继续复用当前策略6详情面板。详情面板增加VCP生命周期、每次收缩振幅与成交量、失效条件。

CSV导出增加VCP观察字段，但不改变旧列。

## 10. `002156`验收样本

使用本地真实日线进行As-Of重放，预期：

- VCP达到两次有效收缩后进入VCP观察板块。
- 2026-07-08显示 `VCP_NEAR_PIVOT`，不再因尾段切分显示 `UNKNOWN` 并完全消失。
- 2026-07-09显示 `VCP_BREAKOUT_CONFIRMED`，新强势启动不能清除VCP身份。
- 2026-07-10至2026-07-14显示 `VCP_POST_BREAKOUT` 或 `VCP_EXTENDED`。
- 偏离支点时不得显示立即买入建议。
- 跌破最后收缩低点且未收复时显示 `VCP_INVALID` 并退出VCP观察板块。

具体首次进入日期由严格As-Of结果决定，不能为了匹配人工日期使用未来K线提前确认。

## 11. 测试计划

### 单元测试

- 两次振幅和成交量依次收缩时确认VCP观察。
- 第二次低点抬高。
- 尾段切分不能隐藏最后一次收缩。
- 新强势启动不能清除突破前VCP身份。
- 突破、突破后、延伸和失效状态转换。
- 延伸状态没有立即买入价格。
- 放量破位和结构低点失效不得进入VCP观察板块。
- 未来K线不能改变历史评估结果。

### 集成测试

- `002156`真实本地数据逐日重放。
- 策略6扫描保存主候选和VCP独立观察记录。
- 数据库、API、CSV和前端字段往返。
- VCP板块允许与重点/观察板块重复显示。
- 旧任务不误显示为VCP观察候选。
- 策略1至策略5回归不受影响。

### 回测和候选审计

- 对修改前后同一历史区间逐日比较VCP观察数量。
- 输出新增、共同、失效和退出股票。
- 检查单日和单月数量，防止观察池无控制膨胀。
- VCP观察层不直接参与正式参数升级；如需把其升级为交易入口，必须单独回测和审批。

## 12. 风险控制

- VCP观察池不能绕过结构低点失效、放量破位、数据和流动性门槛。
- 观察资格不能生成虚假的建议买价、止损位或目标收益。
- 不能因为候选数量目标放宽收缩顺序、成交量收缩或低点不下移条件。
- 突破后观察期必须有限，避免长期占据列表。
- 所有状态按评估日重建，禁止使用未来数据确认过去的VCP。

## 13. 交付标准

1. `002156`不再因尾段切分和新启动重置而丢失VCP观察身份。
2. 前端出现与现有板块同级的“VCP形态候选”。
3. VCP股票仍保留在原重点/观察板块。
4. 交易分类和VCP观察身份没有互相冒充。
5. 旧API和旧任务兼容。
6. 有修改前后真实数据候选比较报告。
7. 策略6专项、后端全量、前端测试和构建通过。

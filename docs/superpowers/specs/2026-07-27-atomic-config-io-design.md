# 配置文件原子读写设计

## 目标

消除 `config.yaml` 在保存中断时被截断为零字节或半文件的风险，并让空文件、非法 YAML、非字典根节点产生明确、可定位的错误。

## 设计

- 新增 `scanner/config_io.py`，作为主程序、Web 服务、维护脚本和策略6研究命令的统一配置 I/O。
- `load_yaml_config(path)` 只接受非空字典根节点；文件为空、YAML 解析失败、根节点不是字典时抛出包含路径和原因的 `ConfigFileError`。
- `write_yaml_config_atomic(config, path)` 在目标文件同目录创建临时文件，完整序列化后执行 `flush()` 和 `os.fsync()`，再重新读取临时文件验证结构，最后通过 `os.replace()` 原子替换目标文件。
- 正式替换前，将原有目标原子复制到已被 Git 忽略的 `data/config-backups/config.yaml.bak`；备份失败时停止替换，保留原配置。备份只保留上一版且可能含旧密钥，不输出到日志或 API。
- 任何序列化、刷盘、验证、备份或替换失败都清理临时文件，并保持原目标内容不变。
- 配置 API 保存失败时返回结构化 HTTP 500，且不得重载 scheduler。
- scheduler 重载仍发生在配置成功落盘之后；重载失败继续明确提示“配置已保存但重载失败”。

## 非目标

- 不自动从 `.bak` 恢复，避免静默覆盖用户当前配置。
- 不改变配置字段、默认值和策略参数。
- 不处理可重新生成的普通报告文件。

## 验收

1. 模拟 YAML 序列化失败时原配置字节完全不变。
2. 成功保存后正式文件是完整新配置，`.bak` 是完整旧配置。
3. 空文件、列表根节点和非法 YAML 返回明确错误，不再出现 `NoneType.get`。
4. `main.py serve` 和 FastAPI 使用同一个加载实现。
5. 配置 API 写入失败不触发 scheduler 重载。

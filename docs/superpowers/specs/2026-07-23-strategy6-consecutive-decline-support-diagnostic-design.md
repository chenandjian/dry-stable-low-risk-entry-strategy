# 策略6连续收跌结构诊断指标设计

## 1. 目标

在策略6候选结果中增加一个“连续收跌结构”诊断指标，帮助人工判断连续回落期间是否同时守住短期低点、且没有异常冲高。该指标只用于候选表、候选详情和导出展示，不参与评分、硬过滤、候选分类、生命周期或交易计划。

## 2. 指标口径

以评估日为最后一根K线，从后向前统计连续收跌交易日：

1. 当日收盘价严格低于前一交易日收盘价，记为一个收跌日。
2. 遇到首个收盘价大于等于前一交易日收盘价的交易日后停止统计。
3. “5日内”是包含收跌日 T 在内的滚动5个交易日，因此以 T 之前4个交易日作为比较基准。
4. T 的最低价必须大于等于此前4日最低价；相等表示守住旧低，只有严格低于才算创滚动5日新低。
5. T 的最高价必须小于等于此前4日最高价；相等不算创滚动5日新高。
6. 不使用首个收跌日作为固定低点基准，也不要求连续收跌期间的最低价逐日抬高。
7. 当且仅当连续收跌天数不少于3、区间中每个收跌日均守住各自滚动5日低且均未创各自滚动5日高时，组合指标判定为通过。
8. 任一收跌日缺少4个前置交易日时，不得判定为通过。

## 3. 输出字段

新增以下策略6诊断字段：

- `consecutive_down_days`：截至评估日的连续收跌天数。
- `consecutive_down_low`：连续收跌区间最低价；无连续收跌时为空。
- `consecutive_down_structure_pass`：是否同时满足“至少3日、守滚动5日低、未创滚动5日高”。
- `consecutive_down_no_new_streak_low`：兼容字段；新任务表示区间内每个收跌日是否均守住各自滚动5日低。数据库列名保持不变，避免破坏旧API。
- `consecutive_down_min_low_margin_pct`：区间内最弱一天相对其此前4日最低价的距离；大于等于0表示守住滚动5日低，数据不足时为空。
- `consecutive_down_max_high_break_pct`：区间内最高价相对其此前4日最高价的最大突破比例；小于等于0表示未创滚动5日新高，数据不足时为空。

旧任务新增列保持 `NULL`，前端显示“未计算”，不得伪造成“不满足”。

## 4. 数据链路

1. `strategy6/indicators.py` 计算诊断指标并写入 `Strategy6Indicators`。
2. `Strategy6Evaluation.to_candidate_dict()` 输出字段。
3. `scanner/db.py` 使用兼容迁移新增列，并完成候选写入、读取和布尔反序列化。
4. 策略6 API 沿用现有候选接口，无需新增接口。
5. `Strategy6Results.vue` 在正式候选表和候选详情中展示，并加入候选CSV导出。

## 5. 前端展示

正式候选表以及“VCP确认候选”“VCP早期观察”共用的VCP观察表均新增“连续收跌结构”列，并作为一个组合指标展示：

- 满足：`3日 · 守5日低 · 未创5日高`
- 连跌不足3日：`2日 · 未满足`
- 连跌达到3日但发生破位或创新高：显示对应未通过原因
- 连跌达到3日但任一天严格跌破此前4日最低价：显示`已破5日低`
- 旧任务无字段：`未计算`

VCP两个板块继续复用同一候选记录和格式化函数，不单独计算指标，不改变VCP质量分、观察池准入、分组或排序。

候选详情展示连续收跌天数、区间最低价、是否守住和最弱余量。

## 6. 兼容与边界

- 不新增配置项，阈值固定为3个收跌日和包含当日在内的滚动5日窗口，避免无必要参数化。
- 不修改策略1至策略5。
- 不修改策略6扫描入口和旧API。
- 不修改任何评分函数、硬过滤函数、分类函数和生命周期函数。
- 回测按评估日截断后的可见K线计算，禁止读取未来数据。

## 7. 测试

1. 连续3日收跌、逐日守住此前4日低且逐日未创此前4日高，组合指标为真。
2. 收跌日最低价等于此前4日最低价时仍通过。
3. 连续3日收跌但其中一天严格跌破此前4日低，组合指标为假。
4. 连续3日收跌但其中一天创滚动5日新高，组合指标为假。
5. 只有2日连续收跌时组合指标为假。
6. 平收或上涨中断连续计数。
7. 前置数据不足时不得误判为真。
8. 新字段通过候选字典、SQLite和API完整往返。
9. 旧任务空字段保持空值。
10. 连续收跌期间低点可以低于首个收跌日，只要当天未严格跌破此前4日最低价即可通过。
11. 相同K线加入该诊断前后总分、拒绝原因和候选分类完全一致。
12. 前端正式候选表、VCP观察表、详情和CSV均展示新字段。

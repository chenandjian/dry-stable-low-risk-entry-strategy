# 策略6连续收跌结构诊断指标设计

## 1. 目标

在策略6候选结果中增加一个“连续收跌结构”诊断指标，帮助人工判断连续回落期间是否同时守住短期低点、且没有异常冲高。该指标只用于候选表、候选详情和导出展示，不参与评分、硬过滤、候选分类、生命周期或交易计划。

## 2. 指标口径

以评估日为最后一根K线，从后向前统计连续收跌交易日：

1. 当日收盘价严格低于前一交易日收盘价，记为一个收跌日。
2. 遇到首个收盘价大于等于前一交易日收盘价的交易日后停止统计。
3. 对连续区间中的每个收跌日 T，计算 T 之前5个交易日的最低价，不包含 T。
4. 对连续区间中的每个收跌日 T，计算 T 之前5个交易日的最高价，不包含 T；T 的最高价不得超过该最高价，等于旧高不算创新高。
5. 首个收跌日建立本轮低点基准；从第二个收跌日起，每日最低价不得低于该基准。相等允许，低于才算本轮创新低；不要求最低价逐日抬高。
6. 当且仅当连续收跌天数不少于3、区间中每个收跌日的最低价都大于等于各自此前5日最低价、后续收跌日未跌破本轮首日低点、且每个收跌日的最高价都小于等于各自此前5日最高价时，组合指标判定为通过。
7. 任一收跌日缺少5个前置交易日时，不得判定为通过。

这样可以避免将当前下跌日纳入5日最低价后产生“条件天然成立”的无效判断。

## 3. 输出字段

新增以下策略6诊断字段：

- `consecutive_down_days`：截至评估日的连续收跌天数。
- `consecutive_down_low`：连续收跌区间最低价；无连续收跌时为空。
- `consecutive_down_structure_pass`：是否同时满足“至少3日、本轮未创新低、守5日低、未创5日高”。
- `consecutive_down_no_new_streak_low`：后续收跌日是否均未跌破本轮首个收跌日低点；少于2个收跌日或数据不足时为空。
- `consecutive_down_min_low_margin_pct`：区间内最弱一天相对其此前5日最低价的距离；数据不足时为空。
- `consecutive_down_max_high_break_pct`：区间内最高价超过其此前5日最高价的最大比例；小于等于0表示未创新高，数据不足时为空。

旧任务新增列保持 `NULL`，前端显示“未计算”，不得伪造成“不满足”。

## 4. 数据链路

1. `strategy6/indicators.py` 计算诊断指标并写入 `Strategy6Indicators`。
2. `Strategy6Evaluation.to_candidate_dict()` 输出字段。
3. `scanner/db.py` 使用兼容迁移新增列，并完成候选写入、读取和布尔反序列化。
4. 策略6 API 沿用现有候选接口，无需新增接口。
5. `Strategy6Results.vue` 在正式候选表和候选详情中展示，并加入候选CSV导出。

## 5. 前端展示

正式候选表以及“VCP确认候选”“VCP早期观察”共用的VCP观察表均新增“连续收跌结构”列，并作为一个组合指标展示：

- 满足：`3日 · 本轮未创新低 · 守5日低 · 未创5日高`
- 连跌不足3日：`2日 · 未满足`
- 连跌达到3日但发生破位或创新高：显示对应未通过原因
- 连跌达到3日但后续最低价跌破本轮首日低点：显示`本轮创新低`
- 旧任务无字段：`未计算`

VCP两个板块继续复用同一候选记录和格式化函数，不单独计算指标，不改变VCP质量分、观察池准入、分组或排序。

候选详情展示连续收跌天数、区间最低价、是否守住和最弱余量。

## 6. 兼容与边界

- 不新增配置项，阈值固定为3个收跌日和前置5日低，避免无必要参数化。
- 不修改策略1至策略5。
- 不修改策略6扫描入口和旧API。
- 不修改任何评分函数、硬过滤函数、分类函数和生命周期函数。
- 回测按评估日截断后的可见K线计算，禁止读取未来数据。

## 7. 测试

1. 连续3日收跌、逐日守住此前5日低且逐日未创此前5日高，组合指标为真。
2. 连续3日收跌但其中一天跌破此前5日低，组合指标为假。
3. 连续3日收跌但其中一天创此前5日新高，组合指标为假。
4. 只有2日连续收跌时组合指标为假。
5. 平收或上涨中断连续计数。
6. 前置数据不足时不得误判为真。
7. 新字段通过候选字典、SQLite和API完整往返。
8. 旧任务空字段保持空值。
9. 连续收跌期间低点可以回落，但只要不低于本轮首日低点即可通过；跌破本轮首日低点必须失败。
10. 相同K线加入该诊断前后总分、拒绝原因和候选分类完全一致。
11. 前端正式候选表、VCP观察表、详情和CSV均展示新字段。

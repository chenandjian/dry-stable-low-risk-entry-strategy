# 新浪 AkShare 前复权与历史 K 线修复设计

## 目标

1. 将生产数据源 `sina` 从新浪未复权 JSONP K 线切换为 AkShare 的新浪前复权接口 `stock_zh_a_daily(adjust="qfq")`。
2. 修复可可靠推断为旧新浪未复权数据写入的 `daily_ohlc` 股票。
3. 数据修复不强制使用新浪，固定按用户指定顺序尝试 `tencent -> sina(AkShare) -> baidu`，选择能完整覆盖现有历史窗口的前复权数据源。
4. 修复实际成功数据源的任务审计，避免 `fallback_source` 继续显示预填源。

## 已确认事实

- `002396` 本地 2026-05-20 收盘为未复权 `33.22`；AkShare 新浪前复权为 `25.38`，百度和腾讯约为 `25.39`。
- `daily_ohlc` 没有来源或复权口径字段。
- 可以从每只股票最后一次非缓存任务的 `source_errors` 按配置源顺序推断实际成功源：首个没有错误记录的数据源即当次成功源。
- 当前可追踪的 5018 只股票中约 1995 只最后一次可推断由新浪写入，20 只无法可靠推断。
- 腾讯当前最多约返回 640 根；数据库常用窗口为 800 根，因此修复不能把腾讯短序列与旧数据按日期合并后冒充完整前复权历史。

## 新浪生产源

`fetch_sina_daily(code, days)` 使用 `ak.stock_zh_a_daily`：

- 沪市 `6xxxxx` 使用 `sh` 前缀。
- 深市 `0xxxxx`、`2xxxxx`、`3xxxxx` 使用 `sz` 前缀。
- 京市 `4xxxxx`、`8xxxxx` 使用 `bj` 前缀。
- 请求全历史前复权数据，按日期升序规范化后取最后 `days` 根。
- OHLC 使用 AkShare 前复权价格；成交量使用 `volume`；成交额优先使用 `amount`，缺失时才用 `volume * close`。
- 空 DataFrame、字段缺失、非法 OHLC 或网络异常均返回 `None`；限流类异常继续抛出，使多源调度记录 `data source busy` 并切换其他源。
- 不允许在 AkShare 失败时回退到旧新浪未复权 JSONP 接口。

## 数据来源审计

扫描成功取得数据后，立即把 `FetchResult` 中的实际 `primary_source`、`fallback_source`、尝试次数、错误和 `source_errors` 写回 `task_stocks`。后续 `scanned/skipped/candidate` 更新不得清空这些字段。

新增 `daily_ohlc_metadata`，以股票代码为主键记录：

- `code`
- `source`
- `price_basis`，本期固定为 `FORWARD_ADJUSTED`
- `row_count`
- `first_date`
- `latest_date`
- `fetched_at`
- `repair_run_id`

旧数据没有元数据时保持兼容，不据此伪造来源。

生产扫描每次从网络源成功取得数据后，必须在同一事务内保存合并后的 OHLC 和实际成功源元数据；缓存直接复用不改写来源。这样后续百度、AkShare新浪或腾讯刷新不会留下过期来源。

## 历史数据修复

修复工具默认 dry-run。候选股票来自每只股票最后一次非缓存任务：

1. 按 `kline_fetched_at/updated_at` 取最新任务。
2. 按当时源链顺序查找首个未出现在 `source_errors` 中的源。
3. 只有推断源为 `sina` 才进入自动修复清单。
4. 所有源均有错误、任务记录缺失或解析失败的股票进入人工复核清单，不自动修改。

修复器使用三个工作线程共享股票队列和 `DataSourceManager`，与正常扫描一致：每个线程按 `tencent -> sina(AkShare) -> baidu` 尝试；数据源已被其他线程占用时立即尝试下一源，因此三个源可并行工作且同一源不会并发请求。若本轮失败且至少一个源为 `busy`，股票最多重新排队3次。该修复顺序不修改生产扫描的 `config.yaml` 数据源顺序：

1. 数据必须通过 OHLC 合法性检查。
2. 新数据行数必须不少于 `min(现有行数, requested_days)`。
3. 新数据最新日期不得早于现有最新日期。
4. 通过后使用该单一来源的完整序列整段替换，禁止与旧序列合并。
5. 同一事务保存 OHLC 和元数据。
6. 单股失败不影响其他股票；保存成功、失败、跳过和来源统计，支持按成功代码断点续跑。

执行真实迁移前使用 SQLite backup API 创建时间戳备份。不得删除备份。迁移报告写入 `docs/reviews/`，包含候选数、成功数、失败数、各数据源成功数、失败清单和 `002396` 修复前后对比。

## 兼容与风险控制

- 不修改策略1至策略6判断逻辑、扫描入口和候选结构。
- 不修改指数数据源。
- 新浪接口批量访问必须串行并保留源链回退，避免高并发触发风控。
- 腾讯不足完整窗口时只能继续尝试下一源，不能保存短序列修复结果。
- 无法证明由新浪写入的数据不自动修改，避免覆盖正确的百度或腾讯历史。
- 修复后的数据会改变历史回测和候选结果，这是纠正价格口径后的预期变化，必须在报告中明确。

## 验收标准

1. 新浪源测试证明调用 `adjust="qfq"`，字段和日期排序正确，只返回最近 `days` 根。
2. `002396` 真实验证中 2026-05-20 收盘约为 `25.38`，2026-05-25 为 `23.90`。
3. 修复工具拒绝短序列、日期倒退、非法 OHLC，并能切换下一数据源。
4. 单股修复整段替换，不保留旧新浪未复权行。
5. 新任务记录真实成功源。
6. 策略1至策略6专项及常规回归无中高等级回归。

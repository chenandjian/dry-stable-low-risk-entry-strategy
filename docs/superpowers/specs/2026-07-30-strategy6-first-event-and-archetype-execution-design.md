# 策略6首次候选事件与分入场类型成交设计

## 1. 目标

在不修改策略6评分、硬过滤、候选分类和生产扫描入口的前提下，研究两个直接影响历史交易结果的环节：

1. 同一强势启动周期只使用首次可执行候选，避免箱体起点、支点或路径变化产生重复和迟到订单。
2. 支撑低吸、支点突破、失败突破回收使用各自匹配的成交触发，不再全部套用同一个买入区开盘规则。

本轮只修改策略6历史研究。旧回测模式保持兼容，研究开关默认关闭，2026年起OOS继续锁定。

## 2. 候选事件身份

新增 `candidate_event_id`，身份只包含：

- 股票代码；
- 当前强势启动日期；
- 决策画像。

同一个强势启动周期内，即使 `setup_id` 因箱体起点、支点或Brooks事件变化而改变，仍属于同一个候选事件。缺少强势启动日期的旧快照回退到原 `setup_id`，禁止把不同未知事件错误合并。

按日期顺序为每个事件输出：

- `candidate_event_sequence`；
- `first_candidate_date` / `is_first_candidate_event`；
- `first_executable_date` / `is_first_executable_event`；
- `first_entry_archetype_date` / `is_first_entry_archetype_event`。

这些字段是历史事实，不加分、不改变正式候选。

## 3. 信号选择模式

回测配置新增 `signal_selection_mode`：

- `LEGACY_SETUP_ID`：保持原行为，每个 `setup_id` 只下第一张可执行订单。
- `FIRST_EVENT_PER_START`：每个 `candidate_event_id` 只使用第一次可执行信号，后续同周期信号只保留在候选明细，不再产生订单。

首次候选若是 `WAIT_BREAKOUT`，可以继续观察；第一次真正可执行的入场原型才允许下单。

## 4. 分入场类型成交

回测配置 `execution.entry_mode` 新增 `ARCHETYPE_TRIGGERED`，旧值 `FROZEN_TRADE_PLAN` 保持不变。

### 4.1 SUPPORT_PULLBACK

- 使用冻结买入区和建议限价；
- 开盘高于买入区时不立即追高，也不立即取消，继续等待有效期内回落；
- 开盘或盘中触及限价时成交；
- 开盘跌破冻结止损时取消。

### 4.2 PIVOT_BREAKOUT

- 使用冻结建议限价或支点作为突破触发价；
- 开盘位于触发价至买入区上沿时按开盘成交；
- 开盘低于触发价、盘中最高价触及触发价时按触发价成交；
- 开盘高于买入区上沿不追高，当日跳过并继续等待有效期。

### 4.3 FAILED_BREAKOUT_RECLAIM

- 使用冻结建议限价或Brooks回收触发价；
- 成交规则与突破触发相同；
- 开盘跌破冻结止损时取消。

`WAIT_BREAKOUT`、`NONE`和未知原型不产生订单。所有成交继续执行A股涨跌停、停牌、T+1、费用、滑点和止损优先语义。

## 5. 实验

- E0：旧setup去重 + 旧冻结成交。
- E1：首次候选事件 + 旧冻结成交。
- E2：旧setup去重 + 分原型成交。
- E3：首次候选事件 + 分原型成交。

训练期固定为2023-2024，验证期固定为2025。冻结信号必须来自同一任务、同一参数集；四个真实宽基指数必须可用；不得读取2026年收益。

## 6. 升级门禁

- 训练和验证期望R均大于0；
- PF均不低于1.20；
- 验证闭合交易不少于30笔；
- 平均盈利R/平均亏损R不低于2.5；
- 候选明细、订单、交易和未成交原因完整可追溯；
- 入围后再执行逐日完整确认和压力测试。

未通过时保留代码、诊断和报告，默认配置继续使用旧模式。

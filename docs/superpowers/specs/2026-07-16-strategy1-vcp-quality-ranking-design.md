# 策略1 VCP 候选质量评分与分级设计

## 1. 背景

策略1当前已经通过 `analyzer/pattern_score.py` 对杯柄和 VCP 计算 0–20 分形态分。VCP 分数包含前期涨幅、收缩次数、深度递减、成交量递减、Pivot 距离和止损距离，并由 `CupHandleStrategyEngine.evaluate_at()` 统一决定候选是否入选。

现有 0–20 分的主要职责是识别和候选门槛判断，档位较粗，多个已经入选的 VCP 候选容易同分，无法稳定回答“当前候选池中哪个 VCP 形态最好”。因此新增一套独立、可解释、可回测的 0–100 分质量评分，用于 VCP 候选内部排序和 S/A/B/C 分级。

## 2. 目标

1. 只对现有策略1 VCP 候选计算质量分，不扩大或缩小候选池。
2. 用 0–100 分及 S/A/B/C 等级区分 VCP 候选的结构质量、突破准备度和风险质量。
3. 给出可解释的子分、主要优点和主要警告。
4. 保证扫描、重新评估、单股回测和策略1历史回测在相同数据切片上结果一致。
5. 保存评分版本和历史明细，为后续验证评分有效性提供可信数据。

## 3. 非目标

- 不修改现有 `vcp_score_20`、`vcp_score_20 >= 13` 或其他候选入选规则。
- 不允许质量分晋级原本未通过的股票，也不允许质量分淘汰原本通过的股票。
- 不给杯柄候选计算 VCP 质量分。
- 不把大盘环境、板块强弱或未来收益纳入质量分。
- 第一版不增加新的正式筛选阈值或页面筛选器。
- 不自动用当前行情回填历史任务。

## 4. 方案选择

### 4.1 采用方案

采用独立的 VCP 质量评分：保留现有 0–20 分负责识别与入选，新增 `vcp_quality_score_100` 负责候选池内部排序和分级。

### 4.2 未采用方案

- 直接把现有 20 分放大到 100 分：改动小，但仍然耦合识别与排序，且同分问题没有根本解决。
- 直接训练数据模型：当前可信回测中的 VCP 机会样本较少，容易过拟合且解释性不足。未来可用回测结果校准规则权重，但不作为第一版实现。

## 5. 业务边界与数据流

```text
日线数据
  -> CupHandleStrategyEngine.evaluate_at()
  -> 现有候选规则生成 evaluation.passed
  -> 仅当 evaluation.passed=true 且 result.pattern_kind="vcp"
  -> 计算 VCP 质量分、等级、理由和警告
  -> 保存到现有候选及策略1回测明细
  -> VCP 分组按质量分降序展示
```

质量评分必须位于策略1统一入口内部，在 `_candidate_rules()` 已经返回结果之后执行。质量评分的结果不得参与 `_candidate_rules()`，也不得修改 `evaluation.passed`、现有策略总分、决策状态或候选数量。

评分实现放在策略1分析边界内的独立模块，例如 `analyzer/vcp_quality.py`。该模块复用 `analyzer.pattern_score` 中的 VCP 收缩检测和 Pivot 口径，不得再实现另一套 VCP 身份或候选识别规则。

## 6. 输出模型

质量评分结果至少包含：

```text
vcp_quality_score_100: int | null
vcp_quality_grade: "S" | "A" | "B" | "C" | null
vcp_structure_score_70: int | null
vcp_readiness_score_20: int | null
vcp_risk_score_10: int | null
vcp_quality_reasons: list[str]
vcp_quality_warnings: list[str]
vcp_quality_version: str | null
```

`null` 表示未评分，与真实 0 分严格区分。杯柄候选、旧任务和整体评分失败的 VCP 候选均使用 `null`，而不是 0。

第一版评分版本固定为 `vcp-quality-v1`。任何公式、权重或等级边界的变更必须更新版本。

## 7. 评分通用规则

1. 只使用评估日及以前的数据，不得读取未来 K 线。
2. 百分比内部统一使用小数，例如 8% 表示为 `0.08`。
3. 所有比率在计算前检查分母大于 0。
4. 连续区间使用线性插值，并将结果截断在该子项的合法分值范围内。
5. 三个一级子分分别在 70、20、10 分内四舍五入为整数，总分使用三个已取整子分相加，保证页面子分之和等于总分。
6. 理由记录得分最高且具有业务含义的 2–3 项；警告记录得分最低或异常的 2–3 项。

线性插值统一使用以下语义：若指标从 `x1` 到 `x2` 时分数从 `s1` 变化到 `s2`，区间内得分为 `s1 + (x-x1)/(x2-x1)*(s2-s1)`；区间外按明确的端点规则处理。

## 8. 形态纯度：70 分

### 8.1 前期上涨基础：8 分

取第一轮收缩高点前最多 60 个交易日的最低价，以该最低价到第一轮高点的涨幅 `prior_gain` 计分：

- `prior_gain <= 10%`：0 分。
- `prior_gain >= 30%`：8 分。
- 10%–30%：从 0 到 8 线性插值。

若第一轮高点前没有有效数据或最低价非正数，记 0 分并产生警告。

### 8.2 收缩次数与结构完整性：10 分

- 少于 2 轮：整体未评分，因为不满足质量评分所需的最小结构。
- 2 轮：6 分。
- 3 轮：9 分。
- 4 轮及以上：10 分。

与现有检测一致，只使用检测器保留的最近 4 轮，不机械奖励更多微小波动。

### 8.3 收缩深度逐轮递减：18 分

对相邻收缩深度 `a`、`b` 计算改善率 `(a-b)/a`：

- 连续性部分 8 分：`8 * 正改善对数 / 相邻对总数`。
- 改善强度部分 10 分：每一对使用 `clamp(改善率/0.35, 0, 1)`，取平均后乘 10。

后一轮不比前一轮浅时，该对在两个部分均不贡献正分。平均每轮缩小 35% 或以上时，改善强度部分达到满分。

### 8.4 收缩成交量逐轮递减：14 分

对相邻轮次平均成交量 `a`、`b` 计算下降率 `(a-b)/a`：

- 连续性部分 6 分：`6 * 正下降对数 / 相邻对总数`。
- 下降强度部分 8 分：每一对使用 `clamp(下降率/0.30, 0, 1)`，取平均后乘 8。

后一轮成交量不低于前一轮时，该对不贡献正分。平均每轮下降 30% 或以上时，下降强度部分达到满分。

### 8.5 最后一轮紧凑度：12 分

使用最后一轮收缩深度：

- `<= 8%`：12 分。
- 8%–12%：从 12 到 8 线性下降。
- 12%–18%：从 8 到 2 线性下降。
- 18%–25%：从 2 到 0 线性下降。
- `>= 25%`：0 分。

### 8.6 节奏质量：8 分

每轮持续日数为 `low_idx - high_idx + 1`，轮次间空档为下一轮 `high_idx` 减上一轮 `low_idx`，整体跨度为最后一轮低点到第一轮高点的含首尾交易日数。

- 持续日数组件 4 分：`4 * 持续 5–25 个交易日的轮次数 / 总轮数`。
- 轮次空档组件 2 分：最大空档不超过 15 日得 2 分；16–30 日得 1 分；超过 30 日得 0 分。
- 整体跨度组件 2 分：15–100 日得 2 分；10–14 日或 101–120 日得 1 分；其他情况得 0 分。

节奏分只评价检测到的结构，不创造或删除收缩轮次。

## 9. 突破准备度：20 分

### 9.1 当前价与 Pivot 距离：8 分

使用现有 `_vcp_pivot()` 口径，距离为 `(pivot-current_close)/pivot`：

- 当前价位于 Pivot 下方 0%–3%：8 分。
- 下方 3%–6%：从 8 到 5 线性下降。
- 下方 6%–10%：从 5 到 0 线性下降。
- 下方超过 10%：0 分。
- 当前价高于 Pivot：0 分，并产生“当前价可能已越过 Pivot”警告。

该警告只影响解释，不替代或改变现有突破排除规则。

### 9.2 末端价格收紧：6 分

先计算每个交易日的真实振幅率：

```text
true_range = max(high-low, abs(high-prev_close), abs(low-prev_close))
true_range_pct = true_range / prev_close
```

比较最近 5 日平均真实振幅率与其之前、不重叠的 20 日平均真实振幅率，得到 `range_ratio`：

- `range_ratio <= 0.60`：6 分。
- 0.60–0.80：从 6 到 3 线性下降。
- 0.80–1.00：从 3 到 0 线性下降。
- `range_ratio >= 1.00`：0 分。

### 9.3 末端量能枯竭：6 分

比较最近 5 日均量与其之前、不重叠的 20 日均量，得到 `volume_ratio`：

- `volume_ratio <= 0.50`：6 分。
- 0.50–0.70：从 6 到 3 线性下降。
- 0.70–1.00：从 3 到 0 线性下降。
- `volume_ratio >= 1.00`：0 分。

## 10. 风险质量：10 分

### 10.1 到末轮低点的止损距离：6 分

以最后一轮低点为结构止损参考，风险距离为 `(current_close-last_low)/current_close`：

- 当前收盘低于末轮低点：0 分，并产生支撑破坏警告。
- 0%–4%：6 分。
- 4%–6%：从 6 到 5 线性下降。
- 6%–8%：从 5 到 3 线性下降。
- 8%–10%：从 3 到 1 线性下降。
- 10%以上：0 分。

### 10.2 支撑完整性：4 分

- 最后一轮低点形成后，没有任何收盘价低于该低点：2 分；否则 0 分并产生警告。
- 最近 10 日没有放量大阴线：2 分；否则 0 分并产生警告。

放量大阴线定义为单日收盘收益小于 -3%，且当日成交量大于该日前 20 日均量的 1.5 倍。基准均量不包含被评估当日；不足 20 个有效基准日时该项记 0 分并产生数据不足警告。

## 11. 等级规则

先按总分生成基础等级：

- S：90–100。
- A：80–89。
- B：70–79。
- C：0–69。

再应用形态纯度上限，避免准备度和低风险掩盖结构不足：

- `vcp_structure_score_70 < 49`：最高为 C。
- `49 <= vcp_structure_score_70 < 56`：最高为 B。
- `vcp_structure_score_70 >= 56`：不限制基础等级。

总分保留原始数值，不因等级上限而重写。发生等级封顶时必须在警告中说明原因。

## 12. 异常与降级

### 12.1 整体未评分

出现以下任一情况时，整体评分返回 `null`：

- 有效收缩少于 2 轮。
- 当前收盘价、Pivot、末轮低点不存在或非正数。
- 评分所需的核心 OHLCV 字段无法转换为有限数值。
- 质量评分模块发生未预期异常。

未预期异常应记录日志，但不得改变候选入选结果或使扫描任务失败。

### 12.2 单项降级

某个非核心比较窗口不足时，该子项记 0 分并增加明确警告，其他子项继续计算。整体至少需要现有 VCP 检测所要求的 60 日数据；末端收紧和量能枯竭正常情况下应具备 25 日不重叠比较窗口。

## 13. 持久化与兼容迁移

### 13.1 实时候选

策略1 `candidates` 表通过 `_ensure_column()` 兼容新增：

- `vcp_quality_score_100 INTEGER`
- `vcp_quality_grade TEXT`
- `vcp_structure_score_70 INTEGER`
- `vcp_readiness_score_20 INTEGER`
- `vcp_risk_score_10 INTEGER`
- `vcp_quality_reasons TEXT`
- `vcp_quality_warnings TEXT`
- `vcp_quality_version TEXT`

理由与警告使用 JSON 数组文本保存。写入和读取必须兼容 `NULL`、空数组以及旧记录。

### 13.2 策略1回测

原始回测信号保存评估日的完整质量评分。机会聚合以首次信号质量分和等级作为主分组依据，避免用后续信号污染首次可交易时点；另外保存机会内最大质量分用于研究评分演化，但不用于首次信号绩效分组。

机会至少保存：

- `first_vcp_quality_score_100`
- `first_vcp_quality_grade`
- `max_vcp_quality_score_100`
- 首次信号三个子分、理由、警告和评分版本

杯柄机会和旧回测任务保持 `NULL`。历史任务不自动回填；显式重新评估时按现有任务数据截止日语义计算。

## 14. API 与前端展示

### 14.1 API

策略1候选 API 返回新增评分字段。字段缺失或为 `NULL` 时，前端按“未评分”处理。API 不因旧任务缺少新字段而失败。

### 14.2 排序

策略1页面继续按 `pattern_kind` 将杯柄与 VCP 独立分组。VCP 分组默认排序：

1. 有质量分的候选优先。
2. `vcp_quality_score_100` 降序。
3. 现有策略总分 `score` 降序。
4. 股票代码升序，保证稳定排序。

杯柄分组保持现有排序，不受 VCP 评分影响。

### 14.3 展示

- VCP 卡片突出显示例如 `S · 92分` 或 `A · 85分`。
- 展开区域显示形态纯度、突破准备度和风险质量三个子分。
- 展示最多 3 条主要优点和 3 条主要警告。
- 杯柄卡片不显示 VCP 质量字段。
- 历史旧任务显示“VCP质量：未评分”，不显示 0 分或 C 级。
- 第一版不新增质量等级筛选器。

前端异步请求继续遵守现有任务上下文和 stale response 防护规则。

## 15. 回测统计与升级边界

策略1可信回测按首次信号质量等级生成：

- 机会数和已入场数。
- 目标率和止损率。
- 平均收益和中位收益。
- 月度分组表现。
- S/A/B/C 之间是否呈现合理的质量梯度。

第一版上线不要求评分立即证明盈利能力。只有同时满足以下条件，未来才可以单独设计“用质量分筛选候选”的规格：

1. 高等级在足够样本下具有更高目标率或收益。
2. 改善存在于多数月份，而非单月偶然。
3. 中位收益与平均收益方向一致。
4. S/A 等级样本数量仍有实用意义。
5. 回测任务完整性和可信度校验通过。

若等级与后续表现不呈合理关系，只能调整评分权重和等级，不得直接改变现有候选规则。

## 16. 测试要求

### 16.1 评分单元测试

- 2、3、4 轮收缩的分数差异。
- 深度严格递减、部分递减和完全不递减。
- 成交量严格递减、仅末轮缩量和末轮放量。
- Pivot 下方各距离边界以及高于 Pivot。
- 末轮紧凑、过宽和止损距离过大。
- 支撑完整、跌破支撑和放量大阴线。
- 所有线性插值端点、总分范围及四舍五入规则。
- S/A/B/C 分界及形态纯度等级上限。
- 数据不足、非法价格、非法成交量和未预期异常。

### 16.2 策略边界测试

- 接入前后同一输入的 `evaluation.passed` 完全一致。
- 接入前后 VCP 候选数量及股票代码集合完全一致。
- 杯柄候选不产生 VCP 质量评分。
- 质量分高低不能晋级或淘汰候选。
- 评分异常时原候选仍能正常保存。
- 扫描、重新评估、单股回测和策略1历史回测在同一评估日得分一致。
- 在评估日以后追加任意 K 线不能改变该评估日的质量分。

### 16.3 数据库与 API 测试

- 新库建表和旧库兼容迁移。
- `NULL` 与真实 0 分的语义。
- JSON 理由和警告的序列化、反序列化。
- 旧任务查询兼容。
- 保存、覆盖重评和读取幂等。
- VCP 分组稳定排序。

### 16.4 前端测试

- VCP 卡片显示等级、总分和三个子分。
- 优点与警告展开显示。
- 杯柄候选不显示 VCP 评级。
- 旧任务显示“未评分”。
- 排序稳定且不受任务切换后的旧异步响应污染。

## 17. 验收标准

实现完成必须满足：

1. 现有候选集合不变，质量评分仅作为 VCP 后置排序和解释字段。
2. 评分总分始终位于 0–100，且等于三个一级子分之和。
3. 杯柄、旧任务、未评分和真实 0 分语义正确。
4. 扫描与回测在同一输入上完全一致且无未来数据泄漏。
5. 数据库兼容迁移、API、前端和回测统计均有自动化测试。
6. 策略1专项测试、后端常规回归、前端测试和构建、Python 编译检查通过。

## 18. 实施顺序建议

1. 以 TDD 实现纯评分模块及边界测试。
2. 接入 `CupHandleStrategyEngine.evaluate_at()`，证明候选集合不变。
3. 增加候选数据库字段、API 序列化和兼容测试。
4. 增加策略1回测信号、机会和分级统计。
5. 增加前端排序、评级与解释展示。
6. 运行专项、回归、构建和扫描/回测一致性验证。

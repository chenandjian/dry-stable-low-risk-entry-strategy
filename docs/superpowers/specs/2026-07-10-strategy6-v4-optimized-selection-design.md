# 策略6 V4 优化选股设计

## 目标

在现有策略6扫描入口上增强强势启动后的 VCP、杯柄和平台尾段识别，优先保留支撑明确、尾部量价收缩、客观盈亏比合格的候选。策略1至策略5不受影响。

## 核心规则

- 启动日、整理段、最近5日尾段严格按时间分割；启动不足5个交易日只标记 `START_CONFIRMED`。
- 形态只使用尾段之前的整理主体，输出 `VCP`、`CUP_HANDLE`、`PLATFORM` 或 `UNKNOWN`，并保存 pivot、形态低点、高度和日期；VCP 不允许跳过中间失败收缩，信号价不得明显低于最后收缩上沿。
- 尾段5日成交量与尾段开始前20日独立基准比较，禁止嵌套窗口自证量干。
- 支撑由形态低点、MA20、近期低点、启动低点等聚类，区分 tactical、key、defense，并使用 ATR 扩展支撑区。
- 客观目标来自历史压力、pivot、形态高度和 ATR；1.5R 至 3.5R 只作为执行目标，不参与客观盈亏比证明。
- 信号收盘后生成，交易计划从下一工作日生效，默认有效3个交易日，并提示 T+1、涨跌停不可成交和费用风险。
- 总分为启动20、形态20、支撑20、尾段20、客观盈亏比10、相对强度与风险10。
- 板块过滤及其配置、评分和输出完全移除，`sector_name` 仅展示；真实市场指数过滤保留。至少两个宽基指数覆盖股票评估日才形成市场状态，RS20 只使用同日沪深300，禁止回退上证指数；沪深300缺失时只允许 WATCH。
- 候选池记录首次/最近出现日期、池龄、退出原因、冷却期和重新入池次数；EXTENDED 作为独立退出状态，不误记为 FAILED。每个任务保存独立生命周期快照，前端和 Excel 将退出/冷却记录与活跃候选分开展示。
- 全局生命周期、任务生命周期快照和活跃候选使用同一 SQLite 事务写入，任一写入失败必须整体回滚。

## 价格口径

项目当前 Baidu、Sina、Tencent 个股日线均按前复权口径使用。本期扫描、形态、支撑和提示性交易计划统一使用前复权价格，并显式输出 `price_basis=FORWARD_ADJUSTED`。`current_price_raw` 不伪造，保持空值。本期不包含真实成交模拟、回测和参数寻优；未来如开发这三类能力，必须另行接入按交易日对齐的未复权价格。

## 兼容性

- 保留策略6原扫描 API、任务类型和候选旧字段。
- `target_price_*`、`risk_reward_ratio_*` 作为旧字段别名继续输出；新调用方应优先使用 `objective_target_*`、`objective_rr_*` 和 `execution_target_*`。
- SQLite 只做增量列迁移，不破坏旧任务。

## 验收

```bash
python -m pytest tests/test_strategy6_*.py -q
python -m compileall scanner strategy6 server.py -q
npm --prefix web test -- --run
npm --prefix web run build
```

验收重点包括阶段不重叠、启动量能和尾段量能基准不重叠、客观盈亏比不自证、板块过滤无残留、市场指数新鲜度和沪深300基准正确、生命周期冷却可追溯、旧 API 与字段兼容。

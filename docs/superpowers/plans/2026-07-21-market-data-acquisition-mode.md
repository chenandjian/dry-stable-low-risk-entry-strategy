# 行情数据获取模式实施计划

## 1. 配置契约

1. 为模式解析和非法值编写失败测试。
2. 新增 `scanner/data_acquisition.py`，定义模式常量、解析函数和配置验证。
3. 在配置保存接口校验模式，正式 `config.yaml` 写入 `tickflow`。

## 2. TickFlow指数能力

1. 先测试四个指数代码映射、`adjust=none`、规范化和写库。
2. 为 `TickFlowBatchClient` 增加独立指数批量请求方法，不改变股票固定 `forward_additive`。
3. 新增 TickFlow 指数更新服务并复用现有 `market_index_ohlc` 接口。
4. 扩展 Web 全量任务状态与报告，覆盖股票和四个指数。

## 3. 扫描前批量准备

1. 测试 TickFlow 模式只更新不新鲜股票、成功股票使用本地新数据、失败股票不回退传统源。
2. 测试传统模式保持现有逐股链。
3. 实现任务级准备会话，向扫描工作线程提供统一 `FetchResult`。
4. 将策略1至策略6扫描入口接入会话，保持策略引擎不变。
5. 测试串行扫描后续策略复用当天缓存，不重复请求。

## 4. 前端配置

1. 先增加页面加载、切换、保存和旧配置默认行为测试。
2. 在策略配置页增加“日线数据获取模式”单选栏。
3. TickFlow 模式说明批量、前复权和不自动回退；传统模式保留数据源选择区。

## 5. 数据清理与验收

1. 运行 TickFlow、六策略扫描入口、配置 API 和前端专项测试。
2. 运行后端完整回归、编译、前端完整测试和构建。
3. 以审核专家角色检查模式泄漏、缓存新鲜度、停牌、部分失败、并发和旧配置兼容。
4. 修复所有中高等级问题并重新验证。
5. 在线备份当前 SQLite，事务清空个股日线、元数据和宽基指数表，验证 `stock_pool` 数量不变。
6. 只提交本任务文件，不纳入用户已有报告改动；提交并推送当前分支。

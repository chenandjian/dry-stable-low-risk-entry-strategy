# 策略6完整VCP轮次开发验收报告

## 1. 验收结论

策略6 V4.6 已将主链和独立观察池统一为“起始峰值 -> 最终低点 -> 已确认反弹峰值”的完整轮次模型。旧的单边下跌段不再单独计为一轮，弱反抽后创新低会继续合并；主链至少需要两轮完整收缩，观察池分为“VCP确认候选”和“VCP早期观察”。

本次未修改策略1至策略5，未调整策略6主候选分数、盈亏比、市场过滤和扫描入口。VCP质量分仍只用于观察池排序和解释，不参与正式候选资格、总分、硬过滤、生命周期和交易计划。

验收状态：**通过，没有遗留中、高等级问题。**

## 2. 核心实现

- 新增 `strategy6/vcp_rounds.py`，主链和观察池不再各自拼接峰谷。
- 一轮完整结构保存峰值、低点、反弹峰值、振幅、反弹幅度、下跌均量、反弹均量和直接突破标记。
- 第一轮振幅限制为 8%-32%；后轮必须满足振幅收紧、下跌量收紧和低点不明显下移。
- 普通反弹最低 3%，至少经过两个可见交易日并由后续回落确认；强势直接突破可在当日确认。
- 历史强势启动存在失败原因时不能成为VCP起点。
- 一轮完整结构进入早期观察；两轮及以上进入确认观察；两者仍必须通过本轮起点后的历史正式候选逐日重放。
- `VCP_QUALITY_V2` 按完整轮次、振幅、下跌量、低点、启动涨幅保留、支点、时间和突破质量计算100分。
- 新增配置、SQLite兼容列、API字段、CSV字段和前端中文展示；旧任务不重算。

## 7. 兼容性与风险

- SQLite只追加兼容列；旧任务不回填、不重算，缺失的新字段返回空对象或NULL。
- 旧VCP质量分继续按V1权重展示；V4.6新任务按V2权重展示。
- 旧配置若只提高第一轮最小振幅而没有新增最大振幅字段，会自动将新上限提升到旧最小值，避免升级后无法启动；显式冲突配置仍拒绝。
- 本次真实验收使用本地真实个股和指数日线，没有调用外部网络源；数据源实时拉取不在本次修改范围。
- 本次验证证明识别、状态、持久化和兼容行为正确，不代表VCP观察池的未来收益已得到统计证明。质量分只用于结构排序，后续收益验证仍应走冻结参数的历史回测/OOS流程。

# 策略5回测性能优化验收报告

## 1. 背景

策略5在 800 根日线数据补齐后，执行真实历史表现回测：

```bash
python -m strategy5.backtester --db data/cuphandle.db --historical-performance --forward-days 5 10 20 --evaluation-step 5 --cooldown-days 10
```

旧实现 600 秒超时，无法完成全市场 `evaluation_step=5` 的真实验证。

## 2. 根因

历史回测对每只股票的每个评估点都执行：

1. `data[:eval_idx + 1]` 创建从上市到评估日的全量切片。
2. 策略5引擎对整段切片重复标准化 OHLC 字段。
3. 指标计算使用 `statistics.mean()`，在大量浮点均值场景下产生额外开销。

100 只股票小样本 profile：

| 阶段 | 评估点 | 耗时 |
| --- | ---: | ---: |
| 优化前 | 5,415 | 32.9 秒 |
| 第一轮：压缩指标窗口 + 快速均值 | 5,415 | 14.0 秒 |
| 第二轮：每股预标准化 K 线 | 5,415 | 3.2 秒 |

## 3. 修复内容

### 3.1 历史回测使用压缩指标窗口

策略5当前指标最大只依赖最近 250 日均线、120 日高点、60 日成交额、20 日强度/高点和短期波动。因此历史回测不需要把评估日前全部日线都传入策略引擎。

新增历史指标窗口：

```text
historical_indicator_window_days = max(260, minimum_kline_days)
```

同时通过 `trading_days_override=eval_idx + 1` 保留原有上市交易日判断语义，不改变 `minimum_trading_days=500` 的过滤结果。

### 3.2 每只股票只标准化一次 K 线

新增 `normalize_rows()`，历史回测读取单股日线后先统一标准化，再在所有评估点复用标准化结果，避免每个评估点重复 `dict.get()` 和 `float()` 转换。

### 3.3 均值计算改为轻量浮点均值

策略5指标只需要普通浮点均值，不需要 `statistics.mean()` 的精确分数求和逻辑。改用内部 `_mean()`，降低均线、成交额均值和均量计算开销。

## 4. 兼容性验证

新增测试覆盖：

1. 压缩窗口 + `trading_days_override` 与完整窗口输出完全一致。
2. 预标准化 K 线与原始 K 线指标结果完全一致。
3. 历史回测实际传入策略引擎的窗口不超过 260 日，并保留真实交易日覆盖值。

## 6. 残余风险

1. 当前优化假设策略5指标不依赖 260 日以前的数据，未来若新增更长周期指标，需要同步提高 `DEFAULT_HISTORICAL_INDICATOR_WINDOW_DAYS` 或改为从指标周期自动推导。
2. 目前仍是单进程回测。71.8 秒已经可用，暂不引入多进程，避免增加 SQLite 读取和跨进程结果聚合复杂度。
3. `events_detail` 默认仍输出前 50 个事件；若未来需要批量导出全部事件，应增加文件输出或分页，避免 CLI 输出过长。

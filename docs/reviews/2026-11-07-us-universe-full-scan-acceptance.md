# 美股股票池与全池研究扫描验收

## 1. 范围与结论

基线 `5e2b2f1`，在 `codex/strategy6-us-market-adaptation` 分支实现TickFlow股票池与全池研究任务。
指数按用户要求搁置，不用ETF代替；forward、原始volume、估算成交额公式和现有策略评分不变。
可通过美股研究页按真实股票池运行，不代表已启用美股正式选股或普通股全市场认证。

## 2. 用户操作

在美股worktree运行前后端，打开“美股研究” `/us/strategy6/research`：

1. 点击“更新股票池（免费端）”。页面展示来源、供应商数量、可扫描数量、待核查数量及快照更新时间。
2. 扫描范围选择“TickFlow全股票池”，无需将上万代码复制到输入框；也可保留手工最多200只的原模式。
3. 留空评估日使用最近完整美股交易日；指定日期明确为历史研究。可选择仅使用本地数据或强制重新拉取。
4. 开始后查看批次、完成/待处理/失败和命中计数。每页50条，“只显示研究命中”由服务端筛选。
5. “停止扫描”在当前批次结束后保留断点；“继续未完成股票”创建后续任务，只处理原任务待处理股票；“仅重试失败股票”另建失败重试任务。

本轮未启动或重启用户现有服务。前端从worktree根目录使用 `npm --prefix web run dev -- --host 127.0.0.1`；后端在另一个终端使用 `python main.py serve --port 8080`，或沿用用户现有端口配置。

## 3. 数据与任务设计

| 文件 | 变化 |
| --- | --- |
| `us_market/universe.py` | 免费 `universes.get('US_Equity')`，验证来源/市场、数量、重复、代码；不可解析代码保留原因 |
| `us_market/repository.py` | `us_universes`不可变快照；`us_job_stocks`逐股终态及分页；事务保存明细和汇总，读一致快照 |
| `us_market/web_task.py` | 手工/全池、冻结快照、20只一批、停止、续跑、失败重试、同任务复用免费客户端 |
| `us_market/service.py` | 在实际网络请求前调用全池节流；缓存命中无需等待 |
| `server.py` | 股票池读/更新、全池参数、分页、停止API；既有CN互斥继续使用 |
| `web/src/pages/USStrategy6Research.vue` | 池来源和数量、范围选择、暂停后继续、失败重试、50条分页 |
| `tests/test_us_market_universe.py` 等 | 真实规模合成场景、API、快照不变、事务回滚、停止续跑和旧任务兼容 |

前端进入页面只读本地快照；手动更新才请求网络。空响应、重复、不一致计数或无可用代码不会覆盖最近成功快照。
新任务以用户选中的快照ID冻结成员，后续刷新股票池不改变运行中任务。原始特殊代码保留在快照待核查清单，不猜测去星号或替换后缀。

每批最多20只，默认1100根日线。对全池实际发出的批次请求至少间隔约1.1秒，具体免费端限制和响应耗时仍由供应商决定。
任务级复用一个无Key客户端，结束释放。每批完成后写入独立逐股表，不把一万多条候选塞进每次轮询JSON。
持久化逐股行保存冻结代码顺序；任务摘要不反复复制完整股票列表与候选明细。
每批的终态写入与汇总同事务，单批无效结果整体回滚，分页、计数、状态从同一SQLite读快照取出。

停止不是中断正在执行的HTTP请求，而是完成当前批再停止。服务进程重启标记INTERRUPTED；手动继续复制已完成与失败行，仅处理PENDING；父任务原记录不变。
重试只取FAILED，保留父任务日期、参数和来源快照；不让全池重试受手工输入200只上限限制。旧小任务可分页及失败重试，不伪造旧任务断点。
继续/重试不会以较新的股票池替换原任务。评估行持有各自行情数据哈希，不声称全市场每只都具有同一取数时刻。

新增接口：

```text
GET  /api/us/data/universe
POST /api/us/data/universe/refresh
POST /api/us/strategy6/research   scope=universe, universe_snapshot_id / resume_of / retry_of
GET  /api/us/strategy6/tasks/{task_id}?page=1&page_size=50&only_passed=false
POST /api/us/strategy6/tasks/{task_id}/stop
```

## 5. 双角色复核与测试

先补失败测试，再实现。重点复核了：

1. 同一池快照在更新后仍可用于原任务；失效响应保留旧快照。
2. 分批持久化，单批错误不会留下半套终态或漂移汇总。
3. 摘要与分页同一读事务，另一个连接提交新批后，当前返回仍前后一致。
4. 停止保存已完成批次；继续只跑未完成；失败重试只跑失败；冻结日期、参数和池。
5. 避免整块JSON重复写结果，分页50条；切任务防旧响应覆盖。
6. 245条合成标的模拟分批评估；12,412条合成标的模拟逐股终态及末页，不将合成结果冒充真实行情。
7. 全池复用SDK、节流，收尾关闭；手工模式限制保留，CN默认及配置不改。

## 6. 剩余限制

- 真实全池K线下载/评估耗时、磁盘占用、免费端缺失率未进行全量在线压力测试。12,386只首轮日线较大，建议先验证小池和目标日期，再手动开始全池任务。
- 不识别或猜测26个特殊代码映射；不宣称当前股票池是历史时点股票池。
- 指数搁置，未开启正式市场过滤、正式候选、收益回测或US定时扫描。
- 尚需完善美股批量评分筛选、候选/VCP持续观察与宽度；本轮不改A股生产逻辑。
- 只支持单后端进程的任务锁；不与CLI并行写同一US库，不把进程重启标为自动恢复完成。

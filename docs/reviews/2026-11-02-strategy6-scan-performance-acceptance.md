# 策略6扫描流程提速验收

## 1. 范围和结论

基线为 `496c196`。开发目录为 `.claude/worktrees/strategy6-strong-vcp-tail`。
优化行情准备、数据库读取、逐股指标计算及VCP历史资格回放，不改变入选规则。

只读本地真实数据的两组完整引擎对比约提速2.23-2.60倍；逐字段输出一致。
这不是全市场在线扫描的端到端测速，不能承诺整个任务缩短相同比例。

## 2. 已确认的瓶颈和修改

| 位置 | 原行为 | 本次修改 |
| --- | --- | --- |
| `strategy6/ttm_squeeze.py` | 每次计算整段历史的布林带、动量和线性回归，最终只输出最新状态 | 保留完整历史的校验、SMA、EMA和Wilder ATR；只计算最后两次动量回归，向前检查当前连续收缩，遇到首次不收缩停止 |

### 请求流水线边界

1. 只有一个请求预取线程，SDK批次请求之间不增加并行调用。
2. 当前批数据被主线程校验、逐股事务入库时，允许请求下一批。
3. 最多保留当前批和下一批，不缓存全市场响应。
4. SQLite、成功/失败回调、进度回调全部保留在调用线程。
5. 某批请求失败只影响该批，后续批次继续；单股错误仍独立处理。
6. 免费/认证模式、`forward_additive`、新鲜度、缺失股票失败列表、人工切换数据模式均未改变。
7. 增量发现复权变化后仍全量刷新；未减少历史长度或跳过数据校验。

## 5. 使用与风险

- 后端进程需要加载新代码后才生效；本次不主动中断正在运行的扫描。
- TickFlow扫描自动开启有界预取，手动和定时扫描复用同一准备函数。
- 此次没有执行全市场真实外部网络回归，远端响应慢、限流和网络失败仍会影响总等待。
- 不引入跨任务指标缓存，避免配置变化、前复权修订或历史更正造成旧结果复用。
- VCP历史资格仍逐日回放；很长的回溯仍可能耗时，但内部计算更快。
- 持续全历史收缩时，为保留准确的连续收缩天数，仍需向前检查整个收缩段。
- 行情全部准备完成后才进入正式逐股扫描；本次只重叠请求与入库，没有改变全任务数据门禁。
- 主链、VCP历史对照为样本验收，不代表对全股票池全部历史日期作了等价证明。
- 用户原有 `config.yaml` 和其他报告修改不在本次提交范围内。
